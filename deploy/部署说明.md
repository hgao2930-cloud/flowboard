# Flowboard 路径部署包

访问入口为 http://8.149.237.91/flowboard/，与原项目共用 Nginx 的 80 端口。原项目继续使用 / 和 /api/。无需额外开放 8080 或 3001。

本包包含 frontend/dist、后端源码及锁文件、shared 文件协议校验模块、建表 SQL、配置模板和说明，不包含真实 .env、密码、数据库数据或 node_modules。部署时 shared 必须与 backend 同级。

## 部署顺序

1. 解压到独立目录，例如 /opt/flowboard。将 frontend/dist 的内容复制到 /var/www/flowboard/，使首页位于 /var/www/flowboard/index.html。不要覆盖原项目的 /var/www/minimall。
2. 使用服务器已有的 Node 24，在 backend 目录执行 `npm ci --omit=dev`。不要上传 Windows 的 node_modules。
3. 在独立 MySQL 库执行 backend/sql/001_rooms.sql，复制 backend/.env.example 为 backend/.env，填写服务器数据库配置，设置 PORT=3001。运行账号仅需白板表的 SELECT/INSERT/UPDATE/DELETE 权限。
4. 在 backend 执行 `npm start`，确认启动后配置后台服务管理。仅支持一个后端进程。部署配置设置 HOST=127.0.0.1，仅由 Nginx 访问后端 3001；安全组不开放 3001。
5. 备份现有 /etc/nginx/conf.d/minimall.conf，在其监听 80 的 server 块内加入 nginx.locations.conf.example 的内容。保留原有 / 和 /api/ 配置。配置片段不能直接放在 conf.d 顶层，因为 location 必须位于 server 内。
6. 执行 `nginx -t`，通过后再重载 Nginx。验证原项目仍然可用，然后访问 /flowboard/。

## 前端路径

生产构建的 base 为 /flowboard/，开发环境仍为 /。路由、资源、HTTP API、WebSocket 和邀请链接都使用相同的 base。

- HTTP：/flowboard/api/rooms，由 Nginx 转为后端 /api/rooms。
- WebSocket：ws://8.149.237.91/flowboard/ws/房间号，由 Nginx 转为后端 /房间号。
- 刷新白板：/flowboard/board/房间号，Nginx 返回白板 index.html，交给前端路由处理。

VITE_WS_URL 仍可覆盖默认 WebSocket 地址，但它是构建时配置。当前包未设置该覆盖值。HTTP 公网 IP 方案不提供传输加密，暂不适合保存敏感内容；以后配置 HTTPS 后，默认连接会自动使用 WSS。

配置依据：[Vite 子路径构建](https://vite.dev/guide/build.html#public-base-path)、[Nginx proxy_pass 路径替换](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)。

## 验收

- 原项目首页和 API 正常。
- /flowboard 自动跳转到 /flowboard/，资源加载正常。
- 创建、加入、分享链接、刷新白板页面正常，两客户端协作正常。
- 等待保存后重启后端，新客户端可以恢复白板。
- 房主删除后另一端退出，旧链接无法重新进入。

默认文档上限 4 MiB，正常变更按两秒窗口保存，数据库失败有限重试。构建成功不代表真实 MySQL 恢复和浏览器交互已验收。
